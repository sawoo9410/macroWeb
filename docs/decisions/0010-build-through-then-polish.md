# ADR-0010 — "다 구축하고 하나씩 손본다": Phase 게이트 완화

- 날짜: 2026-11-03 · 상태: 채택 · 관련: PLAN §0.1-1(Phase 순서), §14 로드맵, ADR-0008(소크 중 Phase 2 시작)

## 맥락
PLAN §0.1-1 은 "현재 Phase 의 DoD 를 전부 통과하기 전에는 다음 Phase 코드를 쓰지 않는다" 고 못 박았다. 구축 이틀째(2026-11-03) 사용자 판단:
"일단 다 구축해놓고 하나씩 손 보자. 시간 문제로 거의 진행을 못한 것 같아. 다음 phase도 진행해."
Phase 2 의 남은 DoD 네 개(T0 diff, 라우팅 실험, 첫 수동 리포트, 평가셋 라벨)는 각각 사람의 시간(라벨 30분·수동 리포트)이나
데이터 축적(라우팅 실험의 100 Story)이 필요해, 게이트를 지키면 Phase 3–5 코드가 며칠 더 늦어진다.

## 결정
1. **구축 우선(build-through).** Phase 3 부터는 DoD 를 "최소 동작(MVP)" 으로 구현하고 다음 Phase 로 넘어간다. 각 Phase 의 미완 항목은
   `docs/phase_status.json` 의 `carry_over` 에 남기고 `current_phase` 는 코드가 시작된 Phase 로 올린다. "다음 가자" 는 이월 항목을 포함해
   가장 앞 Phase 의 미완 항목부터 본다.
2. **불변 규칙은 그대로.** 출처 없는 숫자·URL 금지, evidence 없는 엣지 금지(Q1), 매수·매도 지시 금지, 비밀값 규칙, idempotent CLI,
   `make doctor` 통과. 속도를 내려고 이것들을 느슨하게 하지 않는다.
3. **사람 손이 필요한 항목은 멈추지 않고 양식만 만든다**(평가셋 라벨 템플릿, 시드 그래프 200/500 확장 양식, 인물 카드). 사용자가 채우면
   그 자리에서 채점·검증이 돌도록 명령을 먼저 둔다.
4. **데이터 축적이 필요한 항목**(통계 엣지 r/lag, 커버리지 4주 중앙값, 라우팅 실험)은 코드와 테스트를 먼저 넣고 "자료 부족" 을 결과로
   명시한다 — 값을 지어 넣지 않는다.
5. 이 ADR 은 PLAN §0.1-1 과 충돌한다(ADR 이 이긴다). 되돌리려면 `current_phase` 를 가장 앞의 미완 Phase 로 내리면 된다.
